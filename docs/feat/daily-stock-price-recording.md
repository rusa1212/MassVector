# 일별 주식 종가 기록 설계 및 작업 내역

작성일: 2026-08-18

## 1. 작업 배경

주식 상세 화면에서 확인되는 최신 시세가 2026년 8월 14일에 머물러 있어,
매일 종가를 영속적으로 기록하고 상세 화면에서 누적 이력을 사용할 수 있도록
수집 구조를 추가했다.

기존 구현은 상세 화면을 열 때마다 공공데이터포털의 주식시세정보 API에서
최근 약 220일 데이터를 조회하는 방식이었다. 별도의 저장소나 정기 실행 작업이
없었기 때문에 다음과 같은 문제가 있었다.

- API 응답에 포함된 기간만 사용할 수 있었다.
- API 장애나 지연 시 상세 화면 전체가 오류 상태가 됐다.
- 매일 종가를 프로젝트에 누적하는 기능이 없었다.
- API 응답을 6시간 캐시하여 새 데이터 공개 후에도 반영이 늦을 수 있었다.

공공데이터포털 안내에 따르면 해당 API는 실시간 데이터가 아니며, 기준일의
데이터는 다음 영업일 오후 1시 이후에 반영된다. 따라서 주말 직후에는 마지막
금요일 데이터가 최신값으로 표시될 수 있다.

## 2. 적용한 구조

종가 수집부터 상세 화면 표시까지의 흐름은 다음과 같다.

```text
GitHub Actions 정기 실행
        ↓
공공데이터포털 API에서 종목별 최근 데이터 조회
        ↓
기존 JSON과 날짜 기준 병합 및 중복 제거
        ↓
web/src/data/stock-prices.json 갱신 및 자동 커밋
        ↓
상세 화면 요청 시 저장 이력과 최신 API 응답 병합
        ↓
차트 및 현재가 표시
```

### 자동 수집 일정

- 실행 시각: 월요일~금요일 14:10 KST
- GitHub Actions cron: `10 5 * * 1-5`
- 데이터 제공 시각인 13:00 이후에 실행하도록 1시간 10분의 여유를 뒀다.
- 휴일 또는 일시적인 API 지연을 고려해 매번 최근 30일을 다시 조회한다.
- 새 종목처럼 저장 이력이 없는 경우에는 최근 400일을 조회해 약 1년치를 백필한다.
- 날짜가 같은 데이터는 최신 응답으로 교체되므로 중복 레코드가 쌓이지 않는다.

금요일 종가는 다음 영업일인 월요일 오후에 공개되므로, 자동 실행도
월요일부터 금요일까지로 설정했다.

## 3. 변경 파일

### `.github/workflows/record-daily-stock-prices.yml`

- 평일 자동 실행 및 수동 실행(`workflow_dispatch`)을 지원한다.
- `PUBLIC_DATA_SERVICE_KEY` Repository Secret을 수집 스크립트에 전달한다.
- 종가 파일에 실제 변경이 있을 때만 GitHub Actions 봇 계정으로 커밋하고 푸시한다.
- 동시에 여러 수집 작업이 실행되지 않도록 concurrency group을 설정했다.

### `web/scripts/update-stock-prices.mjs`

- `web/src/data/stocks.ts`에서 국내 6자리 종목 코드를 자동 추출한다.
- 종목별 API 요청은 최대 3회 재시도한다.
- API 응답을 OHLCV 형식으로 변환한다.
- 기존 데이터와 신규 데이터를 날짜 기준으로 병합하고 오름차순 정렬한다.
- 임시 파일 작성 후 rename하는 방식으로 저장하여 기록 중 파일 손상 가능성을 줄였다.

로컬에서는 다음 명령으로 실행할 수 있다.

```bash
cd web
npm run prices:update
```

로컬 실행 시 `web/.env.local`에 다음 환경변수가 필요하다.

```env
PUBLIC_DATA_SERVICE_KEY=공공데이터포털_인증키
```

### `web/src/data/stock-prices.json`

- 종목 코드를 키로 사용하고 각 종목의 OHLCV 배열을 저장한다.
- 최초 작업에서 32개 종목에 대해 각각 267거래일을 백필했다.
- 최초 저장 범위는 2025-07-14부터 2026-08-14까지다.
- 최초 파일 크기는 약 1.29MB다.

저장 형식은 다음과 같다.

```json
{
  "005930": [
    {
      "date": "2026-08-14",
      "open": 0,
      "high": 0,
      "low": 0,
      "close": 0,
      "volume": 0
    }
  ]
}
```

위 숫자는 형식 설명을 위한 예시이며 실제 파일에는 API에서 수집한 값이 저장된다.

### `web/src/lib/publicStockPrices.ts`

- 저장된 JSON 이력과 API에서 가져온 데이터를 날짜 기준으로 병합한다.
- 병합된 데이터의 마지막 두 종가를 이용해 현재가, 등락액, 등락률을 계산한다.
- API 요청, 응답 파싱 또는 API 결과가 실패하면 마지막 저장 이력을 반환한다.
- API 캐시 갱신 간격을 6시간에서 1시간으로 단축했다.

### 기타 파일

- `web/package.json`: `prices:update` 명령 추가
- `web/.env.example`: GitHub Actions Repository Secret 설정 안내 추가
- `web/README.md`: 일별 종가 수집 운영 방법 추가

## 4. 운영 설정

자동 수집을 활성화하려면 다음 설정이 필요하다.

1. 이번 변경사항을 기본 브랜치에 커밋하고 푸시한다.
2. GitHub 저장소의 `Settings > Secrets and variables > Actions`로 이동한다.
3. Repository Secret 이름을 `PUBLIC_DATA_SERVICE_KEY`로 등록한다.
4. `Actions > Record daily stock prices`에서 워크플로를 한 번 수동 실행해 확인한다.
5. 실행 후 `web/src/data/stock-prices.json` 갱신 커밋이 생성됐는지 확인한다.

브랜치 보호 규칙이 GitHub Actions의 직접 push를 금지한다면 워크플로의 자동 커밋이
실패할 수 있다. 이 경우 Actions 봇의 push를 허용하거나 PR 생성 방식으로 변경해야 한다.

## 5. 장애 및 누락 처리

- 수집 요청 실패: 한 종목당 최대 3회 재시도한다.
- 워크플로 실행 실패: 다음 실행이 최근 30일을 다시 조회하여 누락을 보완한다.
- 휴장일: 신규 데이터가 없으면 파일을 커밋하지 않는다.
- API 장애 중 상세 조회: 저장된 마지막 이력을 사용한다.
- 같은 날짜 데이터 재수집: 중복 추가하지 않고 최신 값으로 교체한다.
- 신규 종목 추가: `stocks.ts`에 등록하면 다음 실행에서 자동 발견하여 백필한다.

## 7. 참고 사항

현재 구조는 별도 데이터베이스 없이 Git 저장소의 JSON 파일을 영속 저장소로 사용한다.
현재 종목 수와 일별 데이터 크기에서는 단순하고 운영하기 쉽지만, 향후 종목 수가
크게 늘거나 수년치 데이터가 누적되면 파일 크기와 자동 커밋 빈도가 증가한다.
그 시점에는 PostgreSQL 또는 시계열 데이터베이스에 `(ticker, date)` 복합 고유키를
두고 upsert하는 구조로 이전하는 것이 적합하다.
